# herdr keybindings for Rex

A Rex keymap that mirrors herdr's `ctrl+b` prefix bindings, so switching between the two terminals keeps one set of reflexes.

`herdr-keybindings.lua` holds the bindings. `KEYBINDINGS.md` records which herdr default each binding answers, which ones differ in meaning, and which ones are deliberately left out.

## Why

herdr and Rex both default to a prefix mode, and herdr's is `ctrl+b`. Running them side by side with different prefixes means relearning pane navigation twice a day. This keymap maps herdr's actions onto Rex actions, keeping the same key after the prefix.

## Install

Copy the keymap into your Rex config, or load it from there.

Option A, copy the bindings into `~/.config/rex/init.lua`:

```sh
cat herdr-keybindings.lua >> ~/.config/rex/init.lua
```

Option B, load it from `~/.config/rex/init.lua`:

```lua
dofile("/absolute/path/to/herdr-keybindings.lua")
```

If a plugin manager owns part of `init.lua`, keep that block intact. The `leaf` plugin, for example, writes a marked block that must stay where it is. Appending after it is safe.

Then reload:

```sh
rex config check
rex config reload
rex keymap
```

## What you get

33 bindings are written in the table, 9 tab jumps are generated by a loop, and 6 resize bindings live in a dedicated mode. Rex reports 48 bindings in total.

- Panes. `h j k l` to focus, `tab` to cycle, `v` and `-` to split, `x` to close, `z` to zoom, `shift+h j k l` to move, `shift+p` to rename.
- Tabs. `c` new, `n` and `p` next and previous, `1` through `9` jump, `shift+t` rename, `shift+x` close.
- Workspaces, which are Rex sessions. `w` picker, `shift+n` new, `shift+w` rename, `shift+d` close, `g` go to anything.
- Resize mode. `r` enters, `h j k l` resize, `enter` exits.
- Global. `s` settings, `shift+r` reload config, `b` sidebar, `?` command palette, `q` hide window.
- `ctrl+b` twice sends a literal `ctrl+b` to the pane.

## Differences from herdr

Five bindings keep the key but change the action, because Rex has no exact equivalent.

- `shift+h j k l` moves a pane in a direction. herdr swaps it with its neighbor. The two agree in simple layouts and can differ in nested ones.
- `[` opens Rex find instead of a copy mode. Rex has no copy mode, and its native scroll and selection cover the same ground.
- `?` opens the Rex command palette. Rex has no keybinding help overlay.
- `q` hides the window. Rex has no detach, so running programs stay attached to the app.
- `t` creates a floating pane, matching a custom herdr binding rather than a herdr default.

Nine herdr actions are not ported. They are the notification jump, worktree actions, scrollback editing, navigate mode, and direct prefix-free chords.

The full accounting, including herdr actions that are unbound by default, is in `KEYBINDINGS.md`.

## Verify

Run these against a live Rex instance.

```sh
rex config check      # binding, mode and action counts
rex config reload     # apply the file
rex keymap            # list every effective binding
```

The expected baseline is 48 bindings and 1 mode. `rex -C "<client>" actions` lists the action names available on a client, which is how each action in this keymap was checked before it was written.

## Sources

herdr defaults come from `herdr --default-config`, with the documented swap and copy mode taken from https://herdr.dev/tui/docs/keyboard/ . Rex action names come from `rex actions` on the client.

## Maintenance

Add a binding only after the action name appears in `rex -C "<client>" actions`. Then add a row to `KEYBINDINGS.md` in the same change.

Recheck herdr defaults after a herdr upgrade with `herdr --default-config`, and update the table when its defaults change.
